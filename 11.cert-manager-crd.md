# 🧩 Problem Statement (Custom Resource Definition for cert-manager)

<details>
<summary>Click to expand the problem statement</summary>

A Kubernetes cluster has cert-manager deployed. Your task is to inspect the cert-manager Custom Resource Definitions and extract specific documentation from them.

Your task is to:

1. Connect to the **correct host**
2. List all **CRDs related to cert-manager** and save the output
3. Extract the **documentation for the subject field** of the Certificate CRD and save the output

```
[candidate@base]$ ssh <hostname>
```

### 📋 Configure the following:

1. Use `kubectl` to list all Custom Resource Definitions related to **cert-manager** and save the output to **`~/resources.yaml`**
   * Use the **default kubectl output format** — do not specify a custom format

2. Use `kubectl` to extract the documentation for the **`subject`** specification field of the **`Certificate`** custom resource and save the output to **`~/subject.yaml`**
   * You may use any kubectl output format — use the default format if unsure

</details>

### 📥 Script : setup_q11_crd.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q11: CRD for cert-manager
# setup_q11_crd.sh
# Installs cert-manager and cleans previous candidate output
# Run on: controlplane node
# ============================================================

set -euo pipefail

CERT_MANAGER_VERSION="v1.14.5"

echo ""
echo "==========================================="
echo " CKA Q11 — Setting up cert-manager scenario..."
echo "==========================================="
echo ""

# ── Step 1: Reset candidate work ─────────────────────────────
echo "[1/3] Resetting candidate work from previous attempt..."
rm -f "$HOME/resources.yaml"
rm -f "$HOME/subject.yaml"
echo "  Candidate files cleared."

# ── Step 2: Install cert-manager if not present ───────────────
echo "[2/3] Checking cert-manager..."
if kubectl get namespace cert-manager &>/dev/null && \
   kubectl get deployment cert-manager -n cert-manager &>/dev/null; then
    echo "  cert-manager already installed — skipping."
else
    echo "  Installing cert-manager $CERT_MANAGER_VERSION..."
    kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/${CERT_MANAGER_VERSION}/cert-manager.yaml

    echo "  Waiting for cert-manager to be Ready..."
    kubectl wait --for=condition=available deployment/cert-manager \
        -n cert-manager --timeout=120s
    kubectl wait --for=condition=available deployment/cert-manager-webhook \
        -n cert-manager --timeout=120s
    kubectl wait --for=condition=available deployment/cert-manager-cainjector \
        -n cert-manager --timeout=120s
    echo "  cert-manager installed and Ready."
fi

# ── Step 3: Verify CRDs are present ──────────────────────────
echo "[3/3] Verifying cert-manager CRDs..."
echo ""
kubectl get crds | grep cert-manager.io
echo ""
echo "✅ Practice scenario is ready!"
echo ""
echo "   cert-manager is installed and CRDs are available."
echo "   💪 Go complete the tasks!"
echo ""
```

</details>

# ✅ Solution

### Step 1: Verify cert-manager is deployed

```bash
kubectl get pods -n cert-manager
```

Expected output:

```
NAME                                       READY   STATUS    RESTARTS   AGE
cert-manager-xxx                           1/1     Running   0          ...
cert-manager-cainjector-xxx                1/1     Running   0          ...
cert-manager-webhook-xxx                   1/1     Running   0          ...
```

---

### Task 1: List all cert-manager CRDs and save to ~/resources.yaml

First check what cert-manager CRDs exist:

```bash
kubectl get crds | grep -E "NAME|cert-manager.io"
```

Expected output:

```
NAME                                         CREATED AT
certificaterequests.cert-manager.io          2026-04-17T17:10:47Z
certificates.cert-manager.io                 2026-04-17T17:10:47Z
challenges.acme.cert-manager.io              2026-04-17T17:10:47Z
clusterissuers.cert-manager.io               2026-04-17T17:10:48Z
issuers.cert-manager.io                      2026-04-17T17:10:48Z
orders.acme.cert-manager.io                  2026-04-17T17:10:48Z
```

Now save using the **default output format** (no `-o` flag):

```bash
kubectl get crds | grep -E "NAME|cert-manager.io" > ~/resources.yaml
```

Verify the file:

```bash
cat ~/resources.yaml
```

Expected output:

```
NAME                                         CREATED AT
certificaterequests.cert-manager.io          2026-04-17T17:10:47Z
certificates.cert-manager.io                 2026-04-17T17:10:47Z
challenges.acme.cert-manager.io              2026-04-17T17:10:47Z
clusterissuers.cert-manager.io               2026-04-17T17:10:48Z
issuers.cert-manager.io                      2026-04-17T17:10:48Z
orders.acme.cert-manager.io                  2026-04-17T17:10:48Z
```

> 💡 The question says **default kubectl output format** — do not add `-o yaml`, `-o json` or any other format flag. The pipe to `grep` is fine as it only filters rows.

---

### Task 2: Extract documentation for the subject field of Certificate CRD

Use `kubectl explain` to extract the documentation for the `subject` field:

```bash
kubectl explain certificate.spec.subject > ~/subject.yaml
```

Verify the file:

```bash
cat ~/subject.yaml
```

Expected output:

```
GROUP:      cert-manager.io
KIND:       Certificate
VERSION:    v1

FIELD: subject <Object>

DESCRIPTION:
    Requested set of X509 certificate subject attributes. More info:
    https://cert-manager.io/docs/...

    ...
    countries          <[]string>
    localities         <[]string>
    organizationalUnits <[]string>
    organizations      <[]string>
    postalCodes        <[]string>
    provinces          <[]string>
    serialNumber       <string>
    streetAddresses    <[]string>
```

> 💡 `kubectl explain` uses the default text format by default — this satisfies "use the default format if unsure". If you want the full recursive output use `kubectl explain certificate.spec.subject --recursive`.

### 🧹 Script : reset_q11_crd.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q11: CRD for cert-manager
# reset_q11_crd.sh
# Removes cert-manager and candidate output files
# Run on: controlplane node
# ============================================================

set -euo pipefail

CERT_MANAGER_VERSION="v1.14.5"

echo ""
echo "==========================================="
echo " CKA Q11 — Restoring cluster to baseline..."
echo "==========================================="
echo ""

# ── Remove candidate output files ────────────────────────────
echo "[1/2] Removing candidate output files..."
rm -f "$HOME/resources.yaml"
rm -f "$HOME/subject.yaml"
echo "  Candidate files removed."

# ── Uninstall cert-manager ────────────────────────────────────
echo "[2/2] Uninstalling cert-manager..."
kubectl delete -f https://github.com/cert-manager/cert-manager/releases/download/${CERT_MANAGER_VERSION}/cert-manager.yaml \
    --ignore-not-found 2>/dev/null || true
kubectl delete namespace cert-manager --ignore-not-found
echo "  cert-manager removed."

echo ""
echo "✅ Cluster is back to baseline!"
echo "   Safe to move to next problem. 🚀"
echo ""
```
