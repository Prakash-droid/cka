# 🧩 Problem Statement (Install Calico CNI)

<details>
<summary>Click to expand the problem statement</summary>

A Kubernetes cluster has been initialized but requires a Container Network Interface (CNI) plugin to enable pod networking. Your task is to install and configure a CNI that meets all requirements.

Your task is to:

1. Connect to the **correct host**
2. Choose and install a CNI plugin from the provided options
3. Verify pod-to-pod communication is working
4. Confirm Network Policy enforcement is supported

```
[candidate@base]$ ssh <hostname>
```

### 📋 Configure the following:

Install and configure a CNI that meets the following requirements:

1. Choose one of the following CNI options to install:
   * **Flannel** (version `0.26.1`): `https://github.com/flannel-io/flannel/releases/download/v0.26.1/kube-flannel.yml`
   * **Calico** (version `3.28.2`): Use the Tigera Operator manifest at `https://raw.githubusercontent.com/projectcalico/calico/v3.28.2/manifests/tigera-operator.yaml`

2. The selected CNI must:
   * Enable **pod-to-pod communication**
   * Support **Network Policy enforcement**
   * Be installed from a **manifest file** (do not use Helm)

# ✅ Solution

<details>
<summary>Click to expand the solution</summary>

### Why Calico over Flannel?

Both options are valid but **Calico** is the correct choice because:
- ✅ Supports **Network Policy enforcement** natively
- ❌ Flannel does **not** support NetworkPolicy — only handles pod-to-pod networking

Since the requirement explicitly states NetworkPolicy support, **Calico is the correct answer**.

---

### Step 1: Verify current cluster state

```bash
kubectl get nodes
```

```bash
kubectl get pods -A
```

---

### Step 2: Apply the Tigera Operator manifest

```bash
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.2/manifests/tigera-operator.yaml
```

Wait for the Tigera Operator to be ready:

```bash
kubectl wait --for=condition=available deployment/tigera-operator \
    -n tigera-operator --timeout=120s
```

---

### Step 3: Download the Calico custom resources file

```bash
curl -O https://raw.githubusercontent.com/projectcalico/calico/v3.28.2/manifests/custom-resources.yaml
```

---

### Step 4: Check the cluster Pod CIDR

Before applying, verify the pod CIDR configured in your cluster:

```bash
kubectl cluster-info dump | grep -m1 cluster-cidr
```

Or check via kubeadm config:

```bash
kubectl get configmap kubeadm-config -n kube-system \
    -o jsonpath='{.data.ClusterConfiguration}' | grep podSubnet
```

Note the CIDR value — default is usually `192.168.0.0/16` for Calico. If your cluster uses a different CIDR (e.g. `10.244.0.0/16`), update it in the next step.

---

### Step 5: Update the CIDR range in custom-resources.yaml

```bash
vim custom-resources.yaml
```

Locate the `cidr` field and update it to match your cluster's pod CIDR:

```yaml
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    ipPools:
    - blockSize: 26
      cidr: 192.168.0.0/16    # ← Update this to match your cluster pod CIDR
      encapsulation: VXLANCrossSubnet
      natOutgoing: Enabled
      nodeSelector: all()
```

Save and exit.

---

### Step 6: Apply the updated custom resources

```bash
kubectl create -f custom-resources.yaml
```

---

### Step 7: Wait for Calico to be ready

```bash
watch kubectl get pods -n calico-system
```

Wait until all pods show `Running`:

```
NAME                                       READY   STATUS    RESTARTS   AGE
calico-kube-controllers-xxx                1/1     Running   0          60s
calico-node-xxx                            1/1     Running   0          60s
calico-typha-xxx                           1/1     Running   0          60s
```

---

### Step 8: Verify nodes are Ready

```bash
kubectl get nodes
```

Expected output:

```
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   ...   v1.x.x
node01         Ready    <none>          ...   v1.x.x
```

---

### Step 9: Verify pod-to-pod communication

```bash
kubectl get pods -n kube-system | grep coredns
```

Expected output — coredns pods now `Running`:

```
coredns-xxx   1/1   Running   0   ...
coredns-xxx   1/1   Running   0   ...
```

---

### Step 10: Verify NetworkPolicy support

```bash
kubectl get installation default
```

Expected output:

```
NAME      AGE
default   2m
```

Calico's NetworkPolicy support is built-in and active by default. ✅

### 🧹 Script : reset_q13_cni.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q13: Install Calico CNI
# reset_q13_cni.sh
# Removes Calico/Flannel installation and candidate files
# Run on: controlplane node
# ============================================================

set -euo pipefail

CALICO_VERSION="v3.28.2"
FLANNEL_VERSION="v0.26.1"

echo ""
echo "==========================================="
echo " CKA Q13 — Restoring cluster to baseline..."
echo "==========================================="
echo ""

# ── Remove candidate YAML files ───────────────────────────────
echo "[1/4] Removing candidate YAML files..."
rm -f "$HOME/tigera-operator.yaml"
rm -f "$HOME/custom-resources.yaml"
rm -f "$HOME/kube-flannel.yml"
echo "  Candidate files removed."

# ── Remove Calico if installed ────────────────────────────────
echo "[2/4] Removing Calico installation..."
if kubectl get namespace tigera-operator &>/dev/null; then

    kubectl delete installation default \
        --ignore-not-found 2>/dev/null || true

    kubectl delete -f https://raw.githubusercontent.com/projectcalico/calico/${CALICO_VERSION}/manifests/tigera-operator.yaml \
        --ignore-not-found 2>/dev/null || true

    kubectl delete namespace tigera-operator \
        --ignore-not-found 2>/dev/null || true
    kubectl delete namespace calico-system \
        --ignore-not-found 2>/dev/null || true
    kubectl delete namespace calico-apiserver \
        --ignore-not-found 2>/dev/null || true

    kubectl get crds | grep projectcalico.org | \
        awk '{print $1}' | \
        xargs -r kubectl delete crd --ignore-not-found 2>/dev/null || true

    kubectl get clusterrolebinding | grep calico | \
        awk '{print $1}' | \
        xargs -r kubectl delete clusterrolebinding \
        --ignore-not-found 2>/dev/null || true

    kubectl get clusterrole | grep calico | \
        awk '{print $1}' | \
        xargs -r kubectl delete clusterrole \
        --ignore-not-found 2>/dev/null || true

    echo "  Calico removed."
else
    echo "  Calico not found — skipping."
fi

# ── Remove Flannel if installed ───────────────────────────────
echo "[3/4] Removing Flannel if installed..."
if kubectl get namespace kube-flannel &>/dev/null; then
    kubectl delete -f https://github.com/flannel-io/flannel/releases/download/${FLANNEL_VERSION}/kube-flannel.yml \
        --ignore-not-found 2>/dev/null || true
    kubectl delete namespace kube-flannel \
        --ignore-not-found 2>/dev/null || true
    echo "  Flannel removed."
else
    echo "  Flannel not found — skipping."
fi

# ── Clean CNI config from nodes ───────────────────────────────
echo "[4/4] Cleaning CNI config from nodes..."
sudo rm -f /etc/cni/net.d/10-calico.conflist
sudo rm -f /etc/cni/net.d/calico-kubeconfig
sudo rm -f /etc/cni/net.d/10-flannel.conflist
sudo rm -rf /var/lib/calico
echo "  CNI config cleaned."

echo ""
kubectl get nodes
echo ""
echo "✅ Cluster is back to baseline!"
echo "   Safe to move to next problem. 🚀"
echo ""
```
