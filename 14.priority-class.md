# 🧩 Problem Statement (Pod Priority — PriorityClass)

<details>
<summary>Click to expand the problem statement</summary>

A Kubernetes cluster requires workload prioritization to be configured so that critical pods are scheduled before lower priority ones.

Your task is to:

1. Connect to the **correct host**
2. Create a **PriorityClass** with an appropriate priority value
3. Update the existing Deployment to **use the new PriorityClass**
4. Ensure the Deployment is **successfully rolled out**

```
[candidate@base]$ ssh <hostname>
```

### 📋 Configure the following:

In the **`task-runner`** namespace:

1. Create a new PriorityClass named **`critical-workload`** with an appropriate priority value (ensure it does not exceed the maximum user-defined priority)
2. Update the existing **`log-collector`** Deployment to use the **`critical-workload`** PriorityClass
3. Ensure the Deployment is successfully deployed after applying the PriorityClass

</details>

### 📥 Script : setup_q14_priorityclass.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q14: Pod Priority (PriorityClass)
# setup_q14_priorityclass.sh
# Re-run safe: only resets candidate work on subsequent runs
# Run on: controlplane node
# ============================================================

set -euo pipefail

NAMESPACE="task-runner"
DEPLOYMENT="log-collector"
PRIORITYCLASS="critical-workload"

echo ""
echo "==========================================="
echo " CKA Q14 — Setting up PriorityClass scenario..."
echo "==========================================="
echo ""

# ── Step 1: Reset candidate work ─────────────────────────────
echo "[1/3] Resetting candidate work from previous attempt..."

# Delete candidate-created PriorityClass
kubectl delete priorityclass "$PRIORITYCLASS" --ignore-not-found

# Delete candidate YAML file
rm -f "$HOME/priorityclass-critical-workload.yaml"

# Check if candidate added priorityClassName to deployment
HAS_PRIORITY=$(kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE" \
    -o jsonpath='{.spec.template.spec.priorityClassName}' 2>/dev/null || true)

if [ -n "$HAS_PRIORITY" ]; then
    echo "  priorityClassName detected on deployment — restoring to original..."
    kubectl replace --force -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: $DEPLOYMENT
  namespace: $NAMESPACE
spec:
  replicas: 1
  selector:
    matchLabels:
      app: log-collector
  template:
    metadata:
      labels:
        app: log-collector
    spec:
      containers:
      - name: busybox
        image: busybox:stable
        command: ["/bin/sh", "-c", "while true; do echo logging; sleep 5; done"]
EOF
    echo "  Deployment restored to original state."
else
    echo "  No candidate changes detected on deployment — skipping restore."
fi

echo "  Candidate work cleared."

# ── Step 2: Create max-user-priority if not present ───────────
echo "[2/3] Checking max-user-priority PriorityClass..."
if kubectl get priorityclass max-user-priority &>/dev/null; then
    echo "  max-user-priority already exists — skipping."
else
    echo "  Creating max-user-priority PriorityClass..."
    kubectl apply -f - <<EOF
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: max-user-priority
value: 1000000000
globalDefault: false
description: "Represents the maximum priority allowed for user-defined classes"
EOF
    echo "  max-user-priority PriorityClass created."
fi

# ── Step 3: Create namespace and deployment if not present ────
echo "[3/3] Checking namespace and deployment..."

if ! kubectl get namespace "$NAMESPACE" &>/dev/null; then
    kubectl create namespace "$NAMESPACE"
    echo "  Namespace created."
else
    echo "  Namespace already exists — skipping."
fi

if ! kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE" &>/dev/null; then
    echo "  Creating deployment '$DEPLOYMENT'..."
    kubectl apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: $DEPLOYMENT
  namespace: $NAMESPACE
spec:
  replicas: 1
  selector:
    matchLabels:
      app: log-collector
  template:
    metadata:
      labels:
        app: log-collector
    spec:
      containers:
      - name: busybox
        image: busybox:stable
        command: ["/bin/sh", "-c", "while true; do echo logging; sleep 5; done"]
EOF
else
    echo "  Deployment already exists — skipping."
fi

# ── Wait for pod to be ready ──────────────────────────────────
echo "  Waiting for pod to be Running..."
kubectl wait --for=condition=available deployment/"$DEPLOYMENT" \
    -n "$NAMESPACE" --timeout=120s
echo "  log-collector is Ready."

echo ""
kubectl get priorityclass
echo ""
echo "✅ Practice scenario is ready!"
echo ""
echo "   Run 'kubectl get priorityclass' to see the boundary hint."
echo "   Go create the PriorityClass and update the Deployment! 💪"
echo ""
```

# ✅ Solution

<details>
<summary>Click to expand the solution</summary>

### Step 1: Check existing PriorityClasses

Before creating a new PriorityClass, verify the existing ones to determine a safe priority value:

```bash
kubectl get priorityclass
```

Example output:

```
NAME                      VALUE        GLOBAL-DEFAULT   AGE
system-cluster-critical   2000000000   false            118d
user-defined priority     1000000000   false            20m
system-node-critical      2000001000   false            118d
```

Key observations:
- `system-cluster-critical` and `system-node-critical` are built-in PriorityClasses reserved for system components
- The **maximum user-defined priority value** allowed is `1000000000`
- Therefore the value for `critical-workload` must be **less than `1000000000`** — we use `999999999`

---

### Step 2: Create the PriorityClass manifest

```bash
vim priorityclass-critical-workload.yaml
```

```yaml
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: critical-workload
value: 999999999
globalDefault: false
description: "High priority class for critical workloads"
```

```bash
kubectl apply -f priorityclass-critical-workload.yaml
```

---

### Step 3: Verify the PriorityClass

```bash
kubectl get priorityclass critical-workload
```

Expected output:

```
NAME                VALUE       GLOBAL-DEFAULT   AGE
critical-workload   999999999   false            10s
```

---

### Step 4: Update the Deployment to use the PriorityClass

```bash
kubectl edit deployment log-collector -n task-runner
```

Add `priorityClassName` under the `spec.template.spec` section:

```yaml
spec:
  template:
    spec:
      priorityClassName: critical-workload   # Add this line
      containers:
      - name: busybox
        image: busybox:stable
        command: ["/bin/sh", "-c", "while true; do echo logging; sleep 5; done"]
```

Save and exit.

---

### Step 5: Verify the Deployment rollout

```bash
kubectl rollout status deployment/log-collector -n task-runner
```

---

### Step 6: Confirm PriorityClass is applied to the pod

```bash
kubectl get pod -n task-runner -o jsonpath='{.items[0].spec.priorityClassName}'
```

Expected output:

```
critical-workload
```

### 🧹 Script : reset_q14_priorityclass.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q14: Pod Priority (PriorityClass)
# reset_q14_priorityclass.sh
# Removes namespace, PriorityClasses and candidate YAML files
# Run on: controlplane node
# ============================================================

set -euo pipefail

NAMESPACE="task-runner"
PRIORITYCLASS="critical-workload"

echo ""
echo "==========================================="
echo " CKA Q14 — Restoring cluster to baseline..."
echo "==========================================="
echo ""

# ── Delete namespace ──────────────────────────────────────────
echo "[1/4] Deleting namespace '$NAMESPACE'..."
kubectl delete namespace "$NAMESPACE" --ignore-not-found
echo "  Namespace and all resources removed."

# ── Delete critical-workload PriorityClass ────────────────────
echo "[2/4] Deleting PriorityClass '$PRIORITYCLASS'..."
kubectl delete priorityclass "$PRIORITYCLASS" --ignore-not-found
echo "  PriorityClass deleted."

# ── Delete max-user-priority PriorityClass ────────────────────
echo "[3/4] Deleting PriorityClass 'max-user-priority'..."
kubectl delete priorityclass "max-user-priority" --ignore-not-found
echo "  max-user-priority PriorityClass deleted."

# ── Delete candidate YAML files ───────────────────────────────
echo "[4/4] Removing candidate YAML files..."
rm -f "$HOME/priorityclass-critical-workload.yaml"
echo "  Candidate files removed."

echo ""
echo "✅ Cluster is back to baseline!"
echo "   Safe to move to next problem. 🚀"
echo ""
```
