# 🛠 Setup Practice Scenario

<details>
<summary>Click to expand setup steps</summary>

| Script | Purpose |
|--------|---------|
| `setup_q10_etcd.sh` | Breaks kube-apiserver etcd-servers config and kube-scheduler CPU requests to simulate migration damage — run before practice (re-run anytime) |

---

### 📥 Script : setup_q10_etcd.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q10: Fix a Damaged etcd Cluster
# setup_q10_etcd.sh
# Breaks kube-apiserver etcd-servers and kube-scheduler CPU
# to simulate post-migration cluster damage
# Re-run safe: always restores then re-breaks
# Run on: controlplane node
# ============================================================

set -euo pipefail

APISERVER_MANIFEST="/etc/kubernetes/manifests/kube-apiserver.yaml"
SCHEDULER_MANIFEST="/etc/kubernetes/manifests/kube-scheduler.yaml"
FAKE_ETCD_IP="11.0.1.110"

echo ""
echo "==========================================="
echo " CKA Q10 — Setting up damaged cluster scenario..."
echo "==========================================="
echo ""

# ── Step 1: Restore any previous damage first ────────────────
echo "[1/4] Restoring any previous damage..."

# Fix etcd-servers if already broken
sudo python3 - <<EOF
import re

with open("$APISERVER_MANIFEST", "r") as f:
    content = f.read()

# Restore correct etcd server if broken
content = re.sub(
    r'--etcd-servers=https://[^:]+:2379',
    '--etcd-servers=https://127.0.0.1:2379',
    content
)

with open("$APISERVER_MANIFEST", "w") as f:
    f.write(content)

print("  kube-apiserver etcd-servers restored.")
EOF

# Fix scheduler CPU if already broken
sudo python3 - <<EOF
import yaml

with open("$SCHEDULER_MANIFEST", "r") as f:
    manifest = yaml.safe_load(f)

containers = manifest["spec"]["containers"]
for container in containers:
    if "resources" in container:
        if "requests" in container["resources"]:
            container["resources"]["requests"]["cpu"] = "100m"

with open("$SCHEDULER_MANIFEST", "w") as f:
    yaml.dump(manifest, f, default_flow_style=False)

print("  kube-scheduler CPU requests restored.")
EOF

# Restart kubelet to apply restored configs
sudo systemctl daemon-reload
sudo systemctl restart kubelet

echo "  Waiting for API server to come back up..."
for i in $(seq 1 30); do
    if kubectl get nodes &>/dev/null; then
        echo "  API server is back up."
        break
    fi
    echo "  Waiting... ($i/30)"
    sleep 5
done

echo "  Previous damage restored."

# ── Step 2: Backup original manifests ────────────────────────
echo "[2/4] Backing up original manifests..."
sudo cp "$APISERVER_MANIFEST" "${APISERVER_MANIFEST}.bak"
sudo cp "$SCHEDULER_MANIFEST" "${SCHEDULER_MANIFEST}.bak"
echo "  Backups created."

# ── Step 3: Break kube-apiserver etcd-servers ────────────────
echo "[3/4] Breaking kube-apiserver etcd-servers config..."

sudo python3 - <<EOF
import re

with open("$APISERVER_MANIFEST", "r") as f:
    content = f.read()

# Change etcd server to wrong IP (simulating migration)
content = re.sub(
    r'--etcd-servers=https://127\.0\.0\.1:2379',
    '--etcd-servers=https://$FAKE_ETCD_IP:2379',
    content
)

with open("$APISERVER_MANIFEST", "w") as f:
    f.write(content)

print("  etcd-servers changed to wrong IP: $FAKE_ETCD_IP")
EOF

# ── Step 4: Break kube-scheduler CPU requests ────────────────
echo "[4/4] Breaking kube-scheduler CPU requests..."

sudo python3 - <<EOF
import yaml

with open("$SCHEDULER_MANIFEST", "r") as f:
    manifest = yaml.safe_load(f)

containers = manifest["spec"]["containers"]
for container in containers:
    if "resources" not in container:
        container["resources"] = {}
    if "requests" not in container["resources"]:
        container["resources"]["requests"] = {}
    container["resources"]["requests"]["cpu"] = 0

with open("$SCHEDULER_MANIFEST", "w") as f:
    yaml.dump(manifest, f, default_flow_style=False)

print("  kube-scheduler CPU requests set to 0.")
EOF

# Restart kubelet to apply broken configs
sudo systemctl daemon-reload
sudo systemctl restart kubelet

echo ""
echo "  Waiting 15 seconds for damage to take effect..."
sleep 15
echo ""
echo "✅ Practice scenario is ready!"
echo ""
echo "   Cluster is now damaged — kubectl commands will fail."
echo "   Investigate and fix the broken components!"
echo "   💪 Go fix the cluster!"
echo ""
```

</details>

# ✅ Solution

<details>
<summary>Click to expand the solution</summary>

### Step 1: Verify the cluster is damaged

```bash
kubectl get nodes
```

Expected error output:

```
The connection to the server 127.0.0.1:6443 was refused — did you specify the right host or port?
```

This confirms the API server is not running.

---

### Step 2: Check static pod manifests for issues

Since kubectl is not working, inspect manifests directly:

```bash
sudo cat /etc/kubernetes/manifests/kube-apiserver.yaml | grep etcd-servers
```

Expected output — wrong IP:

```
- --etcd-servers=https://11.0.1.110:2379
```

This is the old IP from before migration. The correct address should be `127.0.0.1`.

---

### Step 3: Fix the kube-apiserver etcd-servers parameter

```bash
sudo vim /etc/kubernetes/manifests/kube-apiserver.yaml
```

Locate the `--etcd-servers` line and fix it:

```yaml
# Wrong — old IP from before migration
- --etcd-servers=https://11.0.1.110:2379

# Correct — local etcd address
- --etcd-servers=https://127.0.0.1:2379
```

Save and exit.

---

### Step 4: Restart kubelet to apply the fix

```bash
sudo systemctl daemon-reload
sudo systemctl restart kubelet
```

Wait for API server to come back:

```bash
for i in $(seq 1 30); do
    if kubectl get nodes &>/dev/null; then
        echo "API server is back up."
        break
    fi
    echo "Waiting... ($i/30)"
    sleep 5
done
```

---

### Step 5: Verify API server is back

```bash
kubectl get nodes
```

If nodes show `Ready` — API server fix is complete. If not, proceed to check scheduler.

---

### Step 6: Check kube-scheduler for issues

```bash
kubectl get pods -n kube-system | grep scheduler
```

If scheduler shows `CrashLoopBackOff` or `Error`:

```bash
kubectl describe pod kube-scheduler-controlplane -n kube-system | grep -A5 "Events:"
```

Or check manifest directly:

```bash
sudo cat /etc/kubernetes/manifests/kube-scheduler.yaml | grep -A5 "requests:"
```

Expected output — CPU set to `0`:

```yaml
requests:
  cpu: 0
```

---

### Step 7: Fix the kube-scheduler CPU requests

```bash
sudo vim /etc/kubernetes/manifests/kube-scheduler.yaml
```

Locate `resources.requests.cpu` and fix it:

```yaml
# Wrong — 0 CPU causes scheduler failure
resources:
  requests:
    cpu: 0

# Correct — set to 100m
resources:
  requests:
    cpu: 100m
```

Save and exit. Kubelet will automatically restart the scheduler.

---

### Step 8: Verify cluster health

Wait 1-2 minutes then verify:

```bash
kubectl get nodes
```

Expected output — all nodes `Ready`:

```
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   ...   v1.x.x
node01         Ready    <none>          ...   v1.x.x
```

```bash
kubectl get pods -n kube-system
```

Expected output — all critical pods `Running`:

```
NAME                                   READY   STATUS    RESTARTS   AGE
coredns-xxx                            1/1     Running   0          ...
etcd-controlplane                      1/1     Running   0          ...
kube-apiserver-controlplane            1/1     Running   0          ...
kube-controller-manager-controlplane   1/1     Running   0          ...
kube-proxy-xxx                         1/1     Running   0          ...
kube-scheduler-controlplane            1/1     Running   0          ...
```

Cluster is fully healthy. ✅
