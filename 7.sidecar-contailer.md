# 🧩 Problem Statement (Sidecar Container Configuration)

<details>
<summary>Click to expand the problem statement</summary>

A Kubernetes cluster has an existing Deployment that needs to be updated to include a sidecar container for log streaming.

Your task is to:

1. Connect to the **correct host**
2. Modify the existing Deployment to **add a sidecar container**
3. Ensure the sidecar has access to the **shared log directory**

```
[candidate@base]$ ssh <hostname>
```

### 📋 Configure the following:

Modify the existing **`data-processor`** Deployment in the **`default`** namespace to add a sidecar container with the following specifications:

* **Image:** `busybox:stable`
* **Command:** `/bin/sh -c "tail -n+1 -f /var/log/data-processor.log"`
* Mount the `/var/log` directory (shared with the main container) to access the `data-processor.log` file

</details>

### 📥 Script : setup_q07_sidecar.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | Q07: Sidecar Container Configuration
# setup_q07_sidecar.sh
# Creates/restores data-processor deployment to original state
# Re-run safe: restores deployment to original on re-run
# Run on: controlplane node
# ============================================================

set -euo pipefail

NAMESPACE="default"
DEPLOYMENT="data-processor"

echo ""
echo "==========================================="
echo " CKA Q07 — Setting up Sidecar scenario..."
echo "==========================================="
echo ""

# ── Step 1: Reset candidate work ─────────────────────────────
echo "[1/2] Resetting candidate work from previous attempt..."

# Check if candidate already added sidecar (2 containers present)
CONTAINER_COUNT=$(kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE" \
    -o jsonpath='{.spec.template.spec.containers}' 2>/dev/null | \
    python3 -c "import sys,json; print(len(json.load(sys.stdin)))" 2>/dev/null || echo "0")

if [ "$CONTAINER_COUNT" -gt 1 ]; then
    echo "  Sidecar detected — deleting and recreating deployment..."
    kubectl delete deployment "$DEPLOYMENT" -n "$NAMESPACE" --force --ignore-not-found
    kubectl wait --for=delete deployment/"$DEPLOYMENT" \
        -n "$NAMESPACE" --timeout=60s 2>/dev/null || true
    echo "  Deployment deleted."
elif [ "$CONTAINER_COUNT" -eq 1 ]; then
    echo "  No candidate changes detected — skipping recreate."
else
    echo "  Deployment not found — will create fresh."
fi

# Create deployment if not present
if ! kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE" &>/dev/null; then
    echo "  Creating deployment '$DEPLOYMENT'..."
    kubectl apply -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: $DEPLOYMENT
  namespace: $NAMESPACE
spec:
  replicas: 1
  selector:
    matchLabels:
      app: data-processor
  template:
    metadata:
      labels:
        app: data-processor
    spec:
      containers:
      - name: main
        image: busybox:stable
        command: ["/bin/sh", "-c"]
        args:
        - |
          mkdir -p /var/log
          while true; do
            echo "\$(date) - data-processor running" >> /var/log/data-processor.log
            sleep 5
          done
EOF
    echo "  Deployment created."
fi

echo "  Candidate work cleared."

# ── Step 2: Wait for pod to be ready ─────────────────────────
echo "[2/2] Waiting for pod to be Running..."
kubectl rollout status deployment/"$DEPLOYMENT" \
    -n "$NAMESPACE" --timeout=120s
echo "  data-processor is Ready."

echo ""
kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE"
echo ""
echo "✅ Practice scenario is ready!"
echo "   Go add the sidecar container! 💪"
echo ""
```

# ✅ Solution

<details>
<summary>Click to expand the solution</summary>

### Step 1: Edit the existing Deployment

```bash
kubectl edit deployment data-processor -n default
```

---

### Step 2: Add the sidecar container and shared volume

Locate the `containers` section and add the sidecar. Also ensure the `log-volume` is mounted in the main container and the volume is defined.

The final spec should look like this:

```yaml
spec:
  template:
    spec:
      containers:
      - name: main
        image: busybox:stable
        command: ["/bin/sh", "-c"]
        args:
        - |
          mkdir -p /var/log
          while true; do
            echo "$(date) - data-processor running" >> /var/log/data-processor.log
            sleep 5
          done
        volumeMounts:                          # Add this to main container
        - name: log-volume
          mountPath: /var/log
      - name: sidecar                          # Add entire sidecar block
        image: busybox:stable
        command:
        - /bin/sh
        - -c
        - "tail -n+1 -f /var/log/data-processor.log"
        volumeMounts:
        - name: log-volume
          mountPath: /var/log
      volumes:                                 # Add volumes section
      - name: log-volume
        emptyDir: {}
```

Save and exit.

---

### Step 3: Verify the Deployment rollout

```bash
kubectl rollout status deployment/data-processor -n default
```

---

### Step 4: Confirm both containers are running

```bash
kubectl get pods -n default
```

```bash
kubectl describe pod <pod-name> -n default
```

Look for **2 containers** listed — `main` and `sidecar`.

---

### Step 5: Verify sidecar is streaming logs

```bash
kubectl logs <pod-name> -c sidecar -n default
```

You should see the log lines being streamed from `data-processor.log`.
