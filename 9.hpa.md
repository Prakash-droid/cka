# 🧩 Problem Statement (Horizontal Pod Autoscaler)

<details>
<summary>Click to expand the problem statement</summary>

A Kubernetes cluster is running a web application deployment that requires dynamic scaling based on CPU load.

Your task is to:

1. Connect to the **correct host**
2. Create a **Horizontal Pod Autoscaler** for the existing deployment
3. Ensure **scale-down behavior** is configured with the correct stabilization window

```
[candidate@base]$ ssh <hostname>
```

### 📋 Configure the following:

* Create an HPA for the **`httpd-frontend`** deployment in the **`scaling-demo`** namespace
* Set the **target CPU utilization** to `50%`
* Set **minimum replicas** to `1`
* Set **maximum replicas** to `4`
* Set the **scale-down stabilization window** to `30 seconds`

</details>

### 📥 Script : setup_q09_hpa.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | q09: Horizontal Pod Autoscaler
# setup_q09_hpa.sh
# Re-run safe: only resets candidate work on subsequent runs
# Run on: controlplane node
# ============================================================

set -euo pipefail

NAMESPACE="scaling-demo"
DEPLOYMENT="httpd-frontend"
HPA="httpd-frontend-hpa"

echo ""
echo "==========================================="
echo " CKA q09 — Setting up HPA scenario..."
echo "==========================================="
echo ""

# ── Step 1: Reset candidate work ─────────────────────────────
echo "[1/4] Resetting candidate work from previous attempt..."
kubectl delete hpa "$HPA" -n "$NAMESPACE" --ignore-not-found
rm -f "$HOME/hpa-httpd-frontend.yaml"
echo "  Candidate work cleared."

# ── Step 2: Install Metrics Server if not present ─────────────
echo "[2/4] Checking Metrics Server..."
if kubectl get deployment metrics-server -n kube-system &>/dev/null; then
    echo "  Metrics Server already installed — skipping."
else
    echo "  Installing Metrics Server..."
    helm repo add metrics-server \
        https://kubernetes-sigs.github.io/metrics-server/ &>/dev/null || true
    helm repo update &>/dev/null
    helm upgrade --install metrics-server metrics-server/metrics-server \
        --namespace kube-system \
        --set "args={--kubelet-insecure-tls,--kubelet-preferred-address-types=InternalIP}"
    echo "  Waiting for Metrics Server to be Ready..."
    kubectl wait --for=condition=available deployment/metrics-server \
        -n kube-system --timeout=120s
    echo "  Metrics Server installed."
fi

# ── Step 3: Create namespace if not present ───────────────────
echo "[3/4] Checking namespace '$NAMESPACE'..."
if kubectl get namespace "$NAMESPACE" &>/dev/null; then
    echo "  Namespace already exists — skipping."
else
    kubectl create namespace "$NAMESPACE"
    echo "  Namespace created."
fi

# ── Step 4: Create deployment if not present ──────────────────
echo "[4/4] Checking deployment '$DEPLOYMENT'..."
if kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE" &>/dev/null; then
    echo "  Deployment already exists — skipping."
else
    echo "  Creating deployment '$DEPLOYMENT'..."
    kubectl create deployment "$DEPLOYMENT" \
        --image=httpd:2.4 \
        --replicas=1 \
        -n "$NAMESPACE"

    echo "  Setting CPU resource requests..."
    kubectl set resources deployment "$DEPLOYMENT" \
        --requests=cpu=100m \
        --limits=cpu=200m \
        -n "$NAMESPACE"

    echo "  Waiting for pod to be Running..."
    kubectl rollout status deployment/"$DEPLOYMENT" \
        -n "$NAMESPACE" --timeout=60s
    echo "  Deployment is Ready."
fi

echo ""
kubectl get deployment "$DEPLOYMENT" -n "$NAMESPACE"
echo ""
echo "✅ Practice scenario is ready!"
echo "   Go create the HPA! 💪"
echo ""
```

</details>

# ✅ Solution

<details>
<summary>Click to expand the solution</summary>

### Step 1: Verify the deployment exists

```bash
kubectl get deployment httpd-frontend -n scaling-demo
```

Confirm it is running before proceeding.

---

### Step 2: Create the HPA

#### Option 1 — Using kubectl autoscale (Quick)

```bash
kubectl autoscale deployment httpd-frontend \
  --name=httpd-frontend-hpa \
  --min=1 \
  --max=4 \
  --cpu-percent=50 \
  -n scaling-demo
```

> 💡 `kubectl autoscale` does not support setting the scale-down stabilization window directly. After running this command, proceed to Step 3 to patch the stabilization window.

---

#### Option 2 — Using YAML manifest (Recommended)

```bash
vim hpa-httpd-frontend.yaml
```

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: httpd-frontend-hpa
  namespace: scaling-demo
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: httpd-frontend
  minReplicas: 1
  maxReplicas: 4
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 30
```

```bash
kubectl apply -f hpa-httpd-frontend.yaml
```

> 💡 YAML approach sets everything in one shot including the stabilization window — preferred when behavior fields are required.

---

### Step 3: Add stabilization window (Only if Option 1 was used)

If you used `kubectl autoscale`, edit the HPA to add the stabilization window:

```bash
kubectl edit hpa httpd-frontend-hpa -n scaling-demo
```

Add the `behavior` block under `spec`:

```yaml
spec:
  minReplicas: 1
  maxReplicas: 4
  behavior:               # Add this block
    scaleDown:
      stabilizationWindowSeconds: 30
```

Save and exit.

---

### Step 4: Verify the HPA

```bash
kubectl get hpa httpd-frontend-hpa -n scaling-demo
```

Expected output:

```
NAME                  REFERENCE                    TARGETS       MINPODS   MAXPODS   REPLICAS
httpd-frontend-hpa    Deployment/httpd-frontend    <unknown>/50%   1       4         1
```

> `<unknown>` is normal if Metrics Server hasn't scraped yet. Wait 30–60 seconds and re-check.

---

### Step 5: Confirm the stabilization window

```bash
kubectl describe hpa httpd-frontend-hpa -n scaling-demo
```

Look for:

```
Behavior:
  Scale Down:
    Stabilization Window: 30 seconds
```

### 🧹 Script : reset_q09_hpa.sh

```bash
#!/bin/bash
# ============================================================
# CKA Practice | q09: Horizontal Pod Autoscaler
# reset_q09_hpa.sh
# Removes HPA, deployment, namespace and candidate YAML files
# Run on: controlplane node
# ============================================================

set -euo pipefail

NAMESPACE="scaling-demo"
DEPLOYMENT="httpd-frontend"
HPA="httpd-frontend-hpa"

echo ""
echo "==========================================="
echo " CKA q09 — Restoring cluster to baseline..."
echo "==========================================="
echo ""

# ── Delete HPA ────────────────────────────────────────────────
echo "[1/4] Deleting HPA '$HPA'..."
kubectl delete hpa "$HPA" -n "$NAMESPACE" --ignore-not-found
echo "  HPA deleted."

# ── Delete deployment ─────────────────────────────────────────
echo "[2/4] Deleting deployment '$DEPLOYMENT'..."
kubectl delete deployment "$DEPLOYMENT" -n "$NAMESPACE" --ignore-not-found
echo "  Deployment deleted."

# ── Delete namespace ──────────────────────────────────────────
echo "[3/4] Deleting namespace '$NAMESPACE'..."
kubectl delete namespace "$NAMESPACE" --ignore-not-found
echo "  Namespace deleted."

# ── Delete candidate YAML files ──────────────────────────────
echo "[4/4] Removing candidate YAML files..."
rm -f "$HOME/hpa-httpd-frontend.yaml"
echo "  Candidate files removed."

# ── Uninstall Metrics Server ──────────────────────────────────
echo "[4/5] Uninstalling Metrics Server..."
if helm status metrics-server -n kube-system &>/dev/null; then
    helm uninstall metrics-server -n kube-system
    echo "  Metrics Server uninstalled."
else
    echo "  Metrics Server not found — skipping."
fi

echo ""
echo "✅ Cluster is back to baseline!"
echo "   Safe to move to next problem. 🚀"
echo ""
```
